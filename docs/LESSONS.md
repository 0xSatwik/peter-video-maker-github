# Lessons (append-only, newest last)

Format: `TRIGGER -> RULE`

- Workflow YAML step name contained ": " (`Verify audio files (guard: need WAVs + metadata)`) -> Never put an unquoted `: ` inside a YAML scalar; GitHub run failed with `mapping values are not allowed here`.
- Cloudflare Worker calling GitHub API got 403 while the same PAT worked from PowerShell -> Cloudflare Workers send no User-Agent; GitHub rejects such requests. Add `"User-Agent": "..."` to every GitHub API call in Functions/Workers.
- Render agent returned `no research available` with 0 urls -> Monid calls need the `/run` suffix (`https://api.monid.ai/v1/run`) and results live at `j.output.results`; also `r.json()` must be parsed once (double parse threw and was silently swallowed).
- Render deploys hung / failed while "build successful" -> the deploy ran node and crashed (`SyntaxError: Unexpected end of input`, a missing `}`); `git push` alone is not enough when using the Render API deploy. Always `node --check` before pushing and read `/v1/logs?resource=<service>` for the runtime error.
- Render wants a GitHub App connection -> not needed for public repos: create/deploy via REST (`POST /v1/services/{id}/deploys` with the API key) and it clones fine.
- Kaggle TTS fails with `Maximum batch GPU session count of 2 reached` -> free-tier GPU quota; workflow now falls back to CPU `edge-tts` (`scripts/tts_cpu.py`) so a run still produces a video.
- actions/upload-artifact failed on `audio/*.wav` -> a stray file named `audio/format: speaker_000.wav` broke the glob (colon in path). Glob explicit `audio/peter_*.wav` + `audio/stewie_*.wav`.
- Render's own `autoDeploy` NEVER fires without a connected GitHub App, so pushed agent code is not deployed automatically -> trigger deploys explicitly (`POST /v1/services/{id}/deploys`) or use the `keep-agent-warm.yml` workflow (needs the `RENDER_API_KEY` repo secret). Symptom: the live agent silently runs days-old code.
- Render free tier sleeps after ~15 min idle, so the first `/api/plan` click can take 30-90s -> the UI must show a live timer (a bare "working..." looks like a hang) and can fire a `/health` warm-up ping on page load.
- GitHub-hosted runner has only 2 vCPU and the per-frame PIL assembly used ~80% of the runtime (25-28 min of 32) -> `scripts/assemble_fast.py` (single ffmpeg filtergraph, unique caption states only) measured 7x faster (25s vs 176s) with ~30 dB PSNR (visually equivalent). Workflow keeps `ASSEMBLE_ENGINE=python` fallback.
- imageio-ffmpeg ships ONLY ffmpeg (no ffprobe), so `ffprobe` calls fail on a local Windows box where that is the only ffmpeg -> `probe_duration()` must fall back to parsing `ffmpeg -i` output.
- OmniVoice voice-quality root cause: reference audio should be 3-10s of clean solo speech, `instruct` must use documented attributes only (an invalid word like `energetic` raises "Unsupported instruct items found" and drops that line), and `num_step=32` is the quality default. Kernel batches per speaker and retries without instruct.
- OmniVoice `instruct` accepts ONLY documented attribute values (gender male/female, age child/teenager/young adult/middle-aged/elderly, pitch very low|low|moderate|high|very high pitch, style whisper, English accents). An invalid word like `energetic` raises `Unsupported instruct items found ...` and FAILS THAT LINE (3/5 clips lost) -> keep instructs inside the documented vocabulary and retry without instruct on rejection.
- OmniVoice voice cloning reference should be 3-10 s of clean solo speech; a 27 s reference degrades similarity. Prefer `assets/peter-voice-latest.mp3` (clean, no background) and pass `instruct` consistent with the reference for stabler clones.
- `kaggle kernels output` crashes on Windows with UnicodeEncodeError (cp1252) because the CLI writes the log with the default encoding -> run with `PYTHONUTF8=1` and capture stdout.
- Kaggle credentials/account changes silently break the pipeline: kernel-metadata `id`, workflow `KERNEL_SLUG`, `scripts/kaggle_run.py` default and the GitHub secrets `KAGGLE_USERNAME`/`KAGGLE_KEY` must all point at the same account (now `satwiksamanta/peter-tts-auto`).
- Videos over ~100 MB exceed sto.care's API limit, so `scripts/upload_temp.py` correctly falls back to gofile (page link, not a direct file).
- storage.to works but multipart assemble payload is undocumented -> `/upload/complete-multipart` returned `MalformedXML`/`Upload is no longer active` for every guess, and a failed assemble invalidates the upload. Skip hosts that require chunked/multipart flows for CI uploads.
- Windows PowerShell here-docs and multi-line `python -c` fail -> write a small `.py`/`.js` file and run it.
- Local `git push` had stale credential-manager creds (`remote: invalid credentials`) -> push via `agent/ghpush.js` (contents API) or set the remote URL with the PAT; also every `git pull --rebase` conflict must be resolved before the next pull ("Pulling is not possible because you have unmerged files").
